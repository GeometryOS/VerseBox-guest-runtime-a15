# 发布流水线

这一篇说明两件事：哪个工作流负责构建，哪个负责发布，以及发布失败时该看哪一行。

## 1. 为什么分成两次动作

构建回答的是这份源码能不能被别人重建成一样的产物。发布回答的是这次发出去的文件有没有经过校验。两条判据的代价不同，构建红了只是这一版不能用，发布错了却会直接出现在公开页面上，删掉之后时间线里仍然留着痕迹。

自动发布省下的只是一次点击。它把误打 tag 的后果直接放大成一次公开行为，而发布还要读历史、写索引，需要写权限，构建不需要。拆开之后构建侧连误写仓库的机会都没有。

## 2. 两个工作流各管什么

| 工作流 | 触发 | 产出 | 权限 |
| --- | --- | --- | --- |
| `.github/workflows/build.yml` | 任意分支推送、拉取请求、推送 tag、手动触发 | 运行时的 tar 包、ROM 包、最小占位包、常驻原生库、打包报告，以及这些文件的哈希清单，统一上传成名为 `a15-runtime` 的附件 | 只读 |
| `.github/workflows/release-publish.yml` | 手动触发，填一个 tag 与一个是否试跑的开关 | GitHub Release，以及索引文件里的一条记录 | 写仓库内容，读 Actions 记录 |

## 3. 什么事件会跑什么

| 事件 | 构建 | 发布 |
| --- | --- | --- |
| 推送分支，改动不在索引目录 | 全量构建 | 不运行 |
| 推送分支，改动只在索引目录 | 跳过 | 不运行 |
| 推送一个 tag | 全量构建 | 不运行 |
| 拉取请求 | 全量构建 | 不运行 |
| 手动触发 | 全量构建，可选择从源码重建宿主 GPU 端点 | 发布指定 tag |

索引目录的跳过规则是给发布收尾准备的。发布工作流把索引写回默认分支，这次提交不改任何源码，重跑一遍构建没有意义。

## 4. 发布工作流按什么顺序做事

| 步骤 | 做什么 | 失败时先看什么 |
| --- | --- | --- |
| 检出 tag | 取这个 tag 的完整历史与标签，正文要用它算区间 | 报浅克隆说明检出深度没设成零 |
| 装 Node | 给三个脚本准备运行时 | 报找不到 node |
| 第一道闸门 | 确认 tag 存在，并且形如版本段带可选后缀 | 报错行里带 tag 原文 |
| 第二道闸门 | 确认这个 tag 上有一次成功的构建 | 日志会列出同一提交上的全部运行，以及各自的名称与结论 |
| 取附件 | 按那次运行的编号下载构建上传的附件 | 报附件不存在，多半是超过保留期 |
| 第三道闸门 | 确认文件齐全，并逐个对上哈希清单 | 报哪个文件的哈希对不上 |
| 第四道闸门 | 让打包器重读 ROM 包内的清单 | 打包器列出的问题条目 |
| 收集附件 | 算出每个附件的哈希与字节数 | 报零字节或缺文件 |
| 生成正文 | 写出正文、标题与版本三个文件 | 报区间、版本或打包报告不一致 |
| 写索引 | 按 tag 覆盖写入一条记录 | 报索引里有不符合格式的旧条目 |
| 试跑 | 打印标题与正文，不发布 | 这一步的内容就是正式发布的内容 |
| 发布 | 建或更新 Release，正文用上一步的文件 | 报附件没匹配上，说明前面漏了文件 |
| 写回索引 | 把索引提交到默认分支 | 看推送与变基的重试记录 |

第二道闸门的判据是 tag 名字，不是提交号。同一个提交常常同时有一次分支构建和一次 tag 构建，两者打包出来的文件名不同，发布必须带 tag 那一次的文件。判据因此写成提交号与名称同时相等。

## 5. 并发与超时

发布工作流的并发组只有一个名字，并且不允许取消已在运行的那一次。同一个 tag 连点两次时第二次排队，第一次写完索引第二次读到的是写完的版本，不会出现两次都在追加。

超时设成九十分钟。下载产物加对一两个 GB 的包算哈希需要几分钟，余量留在这里。超过九十分钟说明在重算不该重算的东西，先看是不是又在本地打了一遍包。

## 6. 产物各是什么

| 文件 | 是什么 | 谁消费 |
| --- | --- | --- |
| 运行时的 tar 包 | prepared 树 | 第三方复现运行时 |
| ROM 包 | 客体内容与自述 | 宿主导入 |
| 最小占位包 | 只声明支持这个系统 | APK 内声明 |
| 常驻原生库的 tar | APK 侧必须带的原生文件 | APK 打包 |
| 打包报告 | 载荷哈希、文件数、承载方式 | 追溯这个包怎么来的 |
| 哈希清单 | 上面全部文件的哈希 | 下载后的校验入口 |

包名里的版本来自运行时仓库的配置文件，与 tag 无关，见[04-VERSION-SOURCES](04-VERSION-SOURCES.md)。
